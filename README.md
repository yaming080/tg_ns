# 도리뉴스 본문·이미지 검증 개선본

검증 상태: **118개 자동 테스트 통과. 실제 AI 생성·이미지 판정과 Telegram 실전 전송은 별도 확인이 필요합니다.**

기준 원본 커밋: `b7b3ae14703395b784246ad3cb0b7360bd40d752`.

## 반영한 사용자 기준

- 뉴스방 최종 수정본처럼 간결한 한국어 본문, 핵심 사실·수치·승인 단계·미확정 조건 보존.
- 인물·기업 한글/영문 검색 태그 보완 및 전체 태그 수 제한.
- 수량만 달라진 반복 매수·보유량 소식 제외. 채널 이력 연결은 제외.
- 광고·불필요 기사·과거 재탕 등 기존 금지 기준을 원문에도 검사. 판단이 불확실하거나 검사가 실패하면 게시하지 않음.
- 이미지가 없거나 검사에 실패하면 글 전체를 보류. 광고·캡처·가격차트·관련 없는 사진을 임의로 게시하지 않음.

## 실제 게시 흐름

RSS 필터/기존 게시 이력 중복 검사 → 원문 기반 요약 → 원문과 사실 대조 → 캡션 검사 → 원문 이미지 후보 검사 → 통과한 이미지 파일 전송 → 게시 이력 저장.

새 이미지 기능은 RSS 이미지, 원문 대표 이미지, article 영역의 이미지 중 최대 3개를 검사한다. 먼저 파일 크기·형식·해상도·배너 비율·파일 손상을 확인한다. 그다음 기존에 설정된 OpenAI 모델에 이미지와 기사 제목·본문을 보내 관련성, 선명도, 광고 아님, 텍스트 캡처 아님, 가격차트 아님을 각각 확인한다. 모든 항목이 명시적으로 통과해야 한다. 검사한 파일 바이트를 그대로 Telegram에 올려, 이후 URL 내용이 바뀌는 문제를 피한다.

인터넷에서 임의의 대체 사진을 검색하거나 사진을 생성하지 않는다. 원문 내 다른 후보도 모두 부적합하면 보류한다. 이미지 모델 검사도 오류 가능성이 있으므로 실제 사례 검증 전 완전 차단을 보장하지 않는다.

API 구현 참고: [공식 OpenAI 이미지 입력 문서](https://developers.openai.com/api/docs/guides/images-vision). 기존 모델 설정을 유지했다. 기본적으로 요약·원문 대조 2회에 이미지 판정이 최대 3회 추가될 수 있고, 긴 요약은 압축 호출이 추가된다.

## 실행과 미리보기

Python 3.11에서:

```powershell
py -m pip install -r requirements.txt
py -X utf8 -m unittest discover -s tests -v
py -X utf8 preview_news.py --input preview_input.json --output preview --limit 5
```

실제 생성에는 환경 변수 `OPENAI_API_KEY`가 필요하다. 키를 코드나 문서에 쓰지 않는다. `OPENAI_MODEL`은 기존 설정을 사용한다. 키가 없으면 모든 입력을 'API 키 미설정'으로 보류하고 그 사실을 미리보기에 표시한다.

`preview/index.html`은 화면용, `preview/results.json`은 검사 결과다. 미리보기는 실제 전송과 동일한 본문·이미지 준비 함수를 호출하지만, Telegram 전송 함수와 게시 상태 저장 함수를 호출하지 않는다. RSS 수집 및 과거 게시 이력 중복 검사 전체를 재현하는 도구는 아니다.

`preview_input.json`에는 제공된 뉴스방 마지막 게시글에서 가져온 검증용 원문 URL 5개가 있다. 제목 필드는 최종본 첫 문장이며 원 RSS 제목이 아니다. 실제 원문을 URL에서 다시 읽어 검사한다. 초기 기준 자료이므로 배포 전 최신 RSS 원문 입력으로도 확인해야 한다.

GitHub에 반영한 뒤에는 별도 `News Preview (no Telegram sending)` 워크플로로 미리보기를 만들 수 있다. 이 워크플로에는 Telegram 토큰을 전달하지 않으며 자동 실행 일정도 없다. 결과는 `news-preview` 아티팩트에 저장된다.

## 백업과 복원

원본 6개 파일과 당시 `news_state.json`을 별도 폴더 `뉴스봇_원본백업_2026-09-26_b7b3ae1` 및 같은 이름의 ZIP으로 보존했다. `BACKUP_MANIFEST.json`의 Git blob SHA가 조회한 GitHub 원본과 모두 일치함을 확인했다.

코드를 되돌릴 때는 원본 봇·편집기·요구사항·워크플로·테스트를 복원한다. **운영이 계속된 뒤에는 오래된 `news_state.json`까지 덮어쓰면 안 된다.** 코드 복원 시 최신 게시 이력을 유지해야 이미 올린 기사를 다시 보내는 일을 피할 수 있다. 백업된 상태 파일은 장애 조사용으로도 보존한다.

GitHub 원본 백업 브랜치: `backup/before-image-review-20260926`. 코드 복원 시 이 브랜치를 참고하되 최신 게시 이력은 유지한다.

## 검증 범위

- 118개 단위·통합 테스트 통과. 기존 83개 중 영문 태그와 수량 변경 정책에 관련된 기대값을 사용자 기준에 맞게 수정했다.
- 새 검사: 이미지 바이트 검증, 사설 주소 거부, 광고 후보 탈락 후 다음 이미지 선택, 필수 판정 누락 시 차단, 검토 파일 그대로 전송, 보류 기사 미전송·미기록, 미리보기 HTML 이스케이프, 본문부터 이미지까지 통합 경로.
- AI 응답은 자동 테스트에서 모의했다. 실제 키를 사용한 요약 품질·비전 정확도·Telegram 실전 전송은 확인하지 않았다.
- 실제 뉴스방 원문 URL 5개로 키 없는 미리보기 실행을 확인했다. 전부 '미검증 보류'이며 완성된 게시물 예시가 아니다.
- 추가한 이미지 기능은 Pillow가 필요하다. 수정본의 requirements.txt를 함께 적용해야 한다.

로컬 전달본에는 변경 비교와 테스트 결과를 함께 보관했다. 코드 업데이트에는 게시 이력 파일을 포함하지 않는다.
